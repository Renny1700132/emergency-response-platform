# G2 术语表

- 状态：DONE（2026-09-13 B 复核通过）
- 用途：SRS、`spec.md`、澄清记录和 RTM 的统一词汇表。

| 术语 | 统一定义 / 使用规则 | 来源 |
| --- | --- | --- |
| 项目 / 本系统 | 某自然博物馆智能运营中心建设项目——应急管理子系统。 | F-001 |
| 甲方 | 课程匿名主体“某自然博物馆”；不虚构现实自然人、职务或法律效力。 | F-001；DEC-012 |
| 乙方 | 本项目的软件建设与交付方；仅承担冻结范围内责任。 | BASELINE-V1.0 |
| MVP | 第二关优先形成和评审的 29 条唯一 FR；不是对其余 10 条 FR 的取消或延期交付。 | 需求确认书 §2—§3 |
| 本期范围 | 全部 39 条 FR 及相关非功能、接口、数据、交付和服务要求。 | KN-063；需求确认书 §3.2 |
| Must | 与 29 条 MVP FR 完全一致的当前优先级。 | G2-01 §3；P2 第2页 |
| Should / Could | 仅表示 MVP 排期优先级；相关 FR 仍属本期验收范围。当前无 Won't。 | G2-01 §4 |
| FR | 功能需求；原始编号 `FR-xx.x` 保留作权威来源编号。 | control/facts.md |
| G2-FR | 第二关人机双镜像稳定编号，与一个原始 FR 一一映射；001—029 为 MVP Must，030—039 为非 MVP、本期范围。 | G2-02 编号规则；ISSUE-G2-06-001 修订 |
| US | G2-01 课程模拟用户故事；与 FR 可以一对多或多对一。 | G2-01 §3 |
| AC | 验收标准编号；格式 `AC-G2-FR-nnn-xx`，由 G2-03/G2-04 对同一需求共同使用。 | P2 第2—4页 |
| Given / When / Then | 前置条件 / 触发行为 / 可观察结果；必须可直接用于测试，不写不可证实的效果口号。 | P2 第2、4页 |
| ★ | 实质性条款，不允许负偏离；不得因局部“宜”字样弱化整条 FR 的★属性。 | F-401；需求确认书 §2 |
| 应 | 强制要求。 | F-401 |
| 宜 | 推荐要求；实施困难时须说明。 | F-401 |
| 可 | 可选能力，不得据此扩大交付承诺。 | F-401 |
| 一张图 | 在统一地图视图中叠加事件、任务、人员、视频、物资站点等业务信息；不等于由乙方重测或新建底图。 | F-009、F-104—F-107 |
| 源精度 | 甲方既有定位系统提供的精度；乙方处理不得降低，但不承担定位基础设施建设。 | F-105；DEC-002 |
| 新鲜度 | 定位数据的时间有效状态；过期或不可用位置只能提示/人工判断，不得冒充实时位置。 | G1 技术复核闭环；G2-01 P-02 |
| 历史回放 | 由既有视频系统提供录像及检索/回放能力，本项目通过接口实现调阅和验证。 | F-106；DEC-001 |
| 应支持门禁联动 | 强制具备受权、安全联锁、失败告警和人工降级的联动能力；不绕过既有门禁安全机制。 | F-138；DEC-003 |
| H5 | 嵌入甲方既有智慧管理 APP 的移动 Web 应用；不等于独立原生 APP。 | F-008；DEC-007 |
| 统一中台 | 甲方既有身份、组织、权限、消息、工作流、文件、门户和数据汇聚等通用能力。 | F-137；DEC-005 |
| 验证 / 验收 | 验证是形成可复核证据；验收是由规定主体按条件确认。需求已澄清不等于技术能力已验证或验收通过。 | BASELINE-V1.0 |
| M2 | 第二关末需求评审门禁；同时也是视频、消息通道连通性验证的最迟节点。 | P2 第3页；F-300 |
| RTM | 需求追踪矩阵，至少建立需求编号到验收标准的正向追踪，并预留设计与测试挂接。 | P2 第3页 |
