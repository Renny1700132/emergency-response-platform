# AGENTS.md —— “澜图”项目 AI 协作规则文件

> 版本 V2.0 · 第 1 关建立（写作期规则）· 第 3 关随 `constitution.md` 扩充（编码期规则）
> 通关实训第 3 组（教学样例）
>
> 本文件是 AI 编码/写作工具**每次会话自动加载**的规则文件。不同工具的加载机制不同，按所选工具放置：
> Cursor 放 `.cursor/rules/`，Claude Code 放 `CLAUDE.md` 或本文件，其余 Agent 工具多数直接识别仓库根目录的 `AGENTS.md`。
> **分工**：本文件管"和 AI 怎么打交道"（事实纪律、编号体系、术语、禁区、协作流程）；`constitution.md` 管"代码怎么写"（技术栈、编码规范、设计约束、门禁）。编码会话两份都要加载。

## 1 项目速览（AI 每次会话的上下文锚点）

- **项目**：澜图遥感影像智能解译工具集，基于开源 `segment-geospatial`（MIT）的行业化二次开发。
- **交付形态**：CLI（7 组 23 条子命令）+ REST 服务（6 个端点）+ QGIS 客户端对接；成果为 GeoTIFF 掩膜与 GeoPackage/Shapefile/GeoJSON 矢量。
- **规格源头**：`spec.md`（24 条 FR + 16 条 NFR + 13 条★）。**任何冲突以 `spec.md` 为准**，其次是 `constitution.md`，再次是本文件，最后才是对话中的口头描述。
- **不在范围**：Web 前端、多用户权限、PostGIS / 对象存储 / 消息队列、等保测评。AI 若生成这些内容，一律视为镀金，拒绝采纳。

## 2 事实纪律（最高优先级）

**F-1 不许编造事实。** 标准编号、条款号、API 签名、函数名、文件路径、性能数值、第三方库能力——凡是可以查证的，必须查证后再写。无法确认的写「待核实」并列入待办，不许用看起来合理的内容填空。

**F-2 数值必须有出处。** 任何容量、耗时、精度、占比数值，要么标注实测来源（脚本、日志、报告编号），要么标注 `【估算，待实测】`。禁止出现无出处的具体数字。

**F-3 引用必须可定位。** 引用国标条款要给到章节号；引用代码要给到文件路径与函数名；引用本项目文档要给到文档编号与小节号。做不到就不引用。

**F-4 不许替人签字。** AI 可以起草评审意见、会议纪要、验收结论，但署名、签署、结论性判定必须由责任人确认后填写。草稿中一律留空并标注「待签署」。

> 这三条不是形式主义。第 1 关的《AI 翻车记录》第 1 条就是 AI 编造了一个不存在的国标条款号并写进了投标书，查标环节才拦下来。

## 3 编号体系（AI 生成任何文档前必须先读）

| 对象 | 格式 | 示例 | 权威定义处 |
| --- | --- | --- | --- |
| 功能需求 | `FR-<模块>.<序号>` | `FR-04.2` | `spec.md` §1 |
| 非功能需求 | `<类别>-<序号>` | `PE-01`、`MTN-03` | `spec.md` §2 |
| 验收标准 | `AC-<需求号>-<字母>` | `AC-FR-04.2-c` | `spec.md` §1 |
| 精度指标 | `AT-<序号>` | `AT-01` | `spec.md` §3 |
| 设计模块 | `M-<序号>` | `M-04` | 概要设计说明书 §4 |
| 架构决策 | `ADR-<序号>` | `ADR-002` | 独立文件 |
| 原子任务 | `T-<序号>` | `T-17` | `tasks.md` |
| 测试用例 | `TC-<需求号>-<序号>` / `UT/IT/ST-<序号>` | `TC-F04-02`、`ST-017` | 测试设计说明书 |
| 缺陷 | `BUG-<序号>` | `BUG-121` | 缺陷看板 |
| 变更单 | `CR-<序号>` | `CR-001` | 变更单文件 |
| 宪章规则 | `R-<序号>` | `R-17` | `constitution.md` |

**编号纪律**：编号一经发布不得复用、不得重排。废弃条目标注「已废止」并保留编号占位。AI 生成文档时若需要新编号，**先读现有最大编号再顺延**，不许自行起号。

## 4 术语表（统一口径，禁止同义词漂移）

| 统一用词 | 禁止使用的说法 | 定义 |
| --- | --- | --- |
| 掩膜 | 蒙版、mask 图、分割图 | 分割输出的栅格图层 |
| 图斑 | 多边形、面要素、polygon | 矢量化后的单个多边形要素 |
| 提示 | prompt、引导、标注点 | 点 / 框 / 文本三类分割输入 |
| 全自动分割 | 自动分割、批量分割 | 无提示、全图目标生成 |
| 交互分割 | 手动分割、点选分割 | 点提示与框提示的合称 |
| 文本提示分割 | 语义分割、开放词汇分割 | 自然语言类别驱动的检测 + 分割 |
| 冻结影像集 | 测试集、验收数据 | 需求确认时封存并记哈希的评测数据 |
| 样例工程 | 参考项目、demo | `sampleprj/segment-geospatial-main` |

英文术语在文档中首次出现时给中文对照，此后统一用中文。代码标识符保持英文原样，不翻译。

## 5 禁区（AI 生成内容的硬性拦截项）

1. **禁止空洞套话**："性能良好""架构先进""充分测试"等无量词表述一律不计分，文档审计直接扣「内容真实性」分。
2. **禁止镀金**：`spec.md` 与 RTM 中没有来源的功能不写、不设计、不实现。
3. **禁止改历史基线**：已签署或已冻结的文档（投标书、需求确认书、项目计划 v1、`constitution.md`）不回改。口径变化用新文档说明。
4. **禁止跨任务发散**：一次会话只做一个任务卡。发现相邻问题登记待办，不顺手改。
5. **禁止用对话记忆当事实源**：结论当日落盘到文档或工作日志，不留在聊天记录里。
6. **禁止无审查采纳**：AI 输出一律经人工逐段审查后入库，PR 中记录审查发现与修改点。

## 6 标准提示词结构（四段式）

所有实质性 AI 任务按四段组织，缺段的提示词质量不合格：

1. **角色与目标**——带约束的角色，不是空头衔。
   *反例*："你是资深工程师"。*正例*："你是本项目的后端工程师，遵守 `constitution.md`，代码评审按 R-01~R-20 清单执行"。
2. **输入与事实**——把依据贴全：相关 `spec.md` 条目、契约片段、设计章节、现有代码。不让 AI 靠猜。
3. **约束**——把本次相关的红线显式列出。**AI 不知道你的红线，除非你每次都说。**
4. **输出规格**——格式、章节、编号规则、篇幅要求、必须包含的字段。

会话结束时的收尾动作三件：产物落盘、任务卡勾选、Prompt 日志归档。

## 7 Prompt 日志规范

- 位置：`logs/prompts/YYYY-MM-DD.md`，按日存放。
- 时点：**当日日志当日写**，最迟次日站会前补齐；补录必须打 `[补录]` 标记并说明原因。
- 值班：每日轮值一人，检查前一日日志与当日 commit 的对照关系。
- 七字段模板：

```
## <时间> | <任务号 T-xx> | <责任人>
- 目标：
- 提示词要点：（四段式的关键约束，不必全文粘贴）
- AI 输出摘要：
- 人工审查发现：
- 采纳/重写比例：
- 关联 commit / PR：
- 备注：
```

> 为什么必须第 1 天就立规：AI 使用贯穿全周期，但审计在第 4 周。日志从第 3 周才开始攒，前两周要么靠回忆补录（不可信），要么直接缺失（扣分）。

## 8 与其他规则文件的关系

```
spec.md          写什么（需求与验收标准）——冲突时最高优先级
constitution.md  代码怎么写（技术栈、规范、门禁）
AGENTS.md        和 AI 怎么打交道（事实纪律、编号、术语、禁区、流程）  ← 本文件
tasks.md         现在做哪一件（原子任务与验证标准）
```

编码会话加载顺序：`constitution.md` → 当前任务卡（`tasks.md` 中的 T-xx）→ 相关 `spec.md` 条目与契约片段。
文档写作会话加载顺序：本文件 → 目标文档的国标章节结构 → 相关 `spec.md` 条目与既有基线文档。
