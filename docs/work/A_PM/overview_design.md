# G3-03 概要设计说明书（工作稿）

状态：DRAFT / SELF_CHECK。依据 G3-01R、G3-02、SRS、spec、RTM；仅定义逻辑架构、模块边界、数据边界与部署约束。

## 1 范围与设计原则

本说明书覆盖 Web、大屏和 H5 渠道接入的应急业务逻辑架构。采用候选 ARC-A 的模块化单体加端口适配和持久化异步任务作为设计候选，最终架构决策仍由后续 ADR 和人工决策确认。原型 Mock、localStorage 和 prototypeStore 不构成设计依据。G3-04 负责物理数据库，G3-05 负责类/状态机细化，G3-06 负责 OpenAPI 和外部字段契约。

## 2 技术架构

渠道经 MOD-PLATFORM 统一 API 边界访问领域模块；MOD-PLAN、EVENT、TASK、SITUATION、RESOURCE、DUTY、DRILL、KNOWLEDGE 和 MOBILE 保持数据写入主责。MOD-INTEGRATION 以独立端口接入外部系统，MOD-PLATFORM 提供鉴权上下文、traceId、审计、配置、幂等、错误语义和健康检查。领域业务提交先持久化，再派生通知、外部调用和态势投影；外部回执不能直接改写业务最终状态。

## 3 数据架构

按领域拥有数据：预案/版本和模板归 MOD-PLAN；事件、续报、核实、关闭材料归 MOD-EVENT；处置任务和消息回执归 MOD-TASK；人员/物资/盘点快照归 MOD-RESOURCE；值班/打卡归 MOD-DUTY；演练/评估归 MOD-DRILL；知识条目归 MOD-KNOWLEDGE。MOD-SITUATION 仅维护可重建读投影。所有跨系统记录保留业务标识、外部标识、traceId 及业务发生/源产生/系统接收/处理时间；不在本说明书定义物理表、字段长度、索引或数据库产品。

## 4 部署与故障域

应用在甲方内部环境以容器制品部署，配置、密钥和日志不进入代码制品。逻辑上分为渠道/API、领域业务、外部适配、数据与可观测性故障域；建议资源 KN-070—078 仅为待验证方案建议。外部适配不可用时，领域状态可继续保存，并记录失败、有限重试和人工处置；控制类指令不得自动重放。健康检查、关联日志、备份恢复演练和干净环境部署是后续验证输入。

## 5 外部边界与 NFR

EXT-VIDEO、PUBLISH、INTRUSION、ACCESS、FIRE、IOT、MIDDLE、MESSAGE 保持独立逻辑语义。甲方提供平台、账号、协议、测试环境及既有能力；本系统负责适配、业务关联、审计、失败处理和约定验证。ISSUE-G3-01-001 仍 OPEN，视频/消息接口字段、认证、回执和性能未验证，故接口仅为候选边界，禁止冻结或宣称连通。KN-064 的视频、信息发布、物联网、中台联动使用同一 traceId/eventId，须分别覆盖正常、无权、超时/失败。

性能约束作为设计预算：预案启动下发≤3秒、告警接入≤2秒、定位刷新≤2秒、视频首帧≤3秒、95%页面≤3秒、峰值≥100人、试运行≥99.5%、单点恢复≤2小时。它们均为待测要求，不是本设计的实测结论。

## 6 追踪

架构元素 ARCH-01 统一渠道/API 边界对应 AC-G2-FR-013-01、013-03；ARCH-02 事件任务编排对应 AC-G2-FR-003-01、014-01、015-01；ARCH-03 资源和快照对应 AC-G2-FR-009-01、025-02；ARCH-04 外部端口与降级对应 AC-G2-FR-006-01、020-02、027-01、029-03；ARCH-05 联动和可观测性对应 AC-G2-FR-006-01、027-01 与 KN-064。G3-08 将逐条挂接 39 FR、34 条★和117 AC。
