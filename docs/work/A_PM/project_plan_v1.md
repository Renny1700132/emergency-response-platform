## 1 编制说明

### 1.1 目的与适用范围

本计划用于组织某自然博物馆智能运营中心建设项目应急管理子系统的需求确认、设计、开发与集成、测试与初验、试运行以及竣工验收。计划以可交付成果为分解对象，明确三名成员的责任、工作包依赖、完成判据和阶段准出条件。项目执行期按合同签订日记为 W1 起点；实际日历日期由合同生效日换算并经甲方确认。

本计划不改变用户需求书规定的正式里程碑、项目范围、验收标准或甲乙双方责任。现场尚未完成的接口、性能、安全、试运行和演练验证均作为后续证据任务安排，不写成已通过结论。

### 1.2 编制依据

1. 《智能运营中心-应急管理子系统 用户需求书》，重点采用第 9.1 节实施周期与 M1—M5、第 9.2 节项目管理、第 9.3 节培训、第 9.5 节风险管理以及第 10 章验收与交付要求。
2. 冻结的 BASELINE-G1-V0.1，采用已确认的范围、关键数字、十二项澄清、外部依赖责任和变更边界。
3. 《项目建议书》V0.2，采用建设范围、实施原则和项目管理建议。
4. 《技术方案》V0.6，采用架构、接口、数据、安全、部署、验证与分阶段准出证据。
5. 项目治理文件，采用三人成员分工、配置管理、文档管理、Git 安全同步和评审闭环规则。

### 1.3 计划口径

- W1 从合同签订日起算，每个 W 表示连续一周。
- 最底层工作包单次执行周期不超过一周。持续性管理项按周重复形成记录，不将多周跨度视为一个不可验证工作包。
- M1、M2、M3、M4、M5 的名称、相对时点和主要交付物按用户需求书第 9.1 节原文执行。
- M4 与 M5 均以试运行满一个月为时间条件。计划在 W20 完成试运行准出证据后组织竣工验收；若甲方验收窗口另行安排，仅调整日历日期，不降低准出条件。

## 2 工作分解结构

### 2.1 分解原则

WBS 按可交付成果分为项目管理与控制、需求确认、设计评审、开发与集成、测试与初验、试运行与竣工验收六个一级分支。每个底层工作包必须形成可审查的文件、软件增量、测试记录或签认材料。学习、一般会议和无交付物的协调活动不单列为工作包。

### 3.2 任务依赖与关键路径

需求确认是设计工作的输入，设计评审是开发与集成的准入门槛。甲方提供的视频、消息、宿主 APP、部署环境和真实业务数据直接影响对应工作包；其中视频与统一消息通道必须在 M2 前完成真实连通性验证。

计划关键路径为：需求条款与 SRS → M1需求确认 → 总体及详细设计 → 视频/消息连通验证 → M2设计评审 → 公共基础与核心业务增量 → 指挥与H5集成 → 外部系统联动 → W14数据初始化候选与W15性能加固 → W15后段单元/集成测试 → W16前段初验部署 → W16性能兼容、安全可移植与功能追踪验证 → M3初验 → 形成试运行启动记录并从该时点连续监测 → W17—W20逐周试运行与真实演练 → W20前段M4试运行准出 → W20后段M5竣工验收。

数据初始化技术实施由 B 在 W14第5个工作日完成，C 仅提供规则、对账口径与符合性输入；W15—W16 的 B 主责工作按 WBS 所列工作日顺序执行，不以同周并列掩盖前置依赖。W17 中 6.1 的培训与 6.2 的首周运行监测并行，试运行连续监测不等待全部培训完成；6.2 的准入依据为 M3 初验包和试运行启动记录。文档编制和测试设计与开发并行推进，但均受阶段评审门禁控制。任一关键路径工作包未满足完成判据，A 不得将后续里程碑写成已达成。

## 5 沟通、配置、文档与 Git 管理

### 5.1 沟通与报告

乙方在合同签订后1周内提交详细项目计划。项目执行期间每周形成周报，内容包括本周进展、下周计划和风险。评审、接口条件、验收窗口与交付签认均形成书面记录。重大风险在识别后24小时内书面报告甲方。

### 5.2 配置与文档管理

- 代码、脚本、配置、文档和测试证据纳入统一版本控制，交付版本建立可追溯标签或基线。
- 文档采用明确的版本号、修订记录、主责和复核状态。需求、设计、测试与实际系统保持双向追踪。
- M1、M2、M3和M5前执行配置审计，核对源代码、构建制品、数据库脚本、配置项、接口契约、文档和测试证据的一致性。
- 甲方可在里程碑节点获取代码快照。对外提交可编辑源文件与PDF，交付格式和内容遵守用户需求书。

### 5.3 Git 工作安排

项目主线使用受控的 master。每项正式任务开始与结束均获取远程最新状态；只允许快进或保留双方历史的普通合并，禁止强制推送和历史重写。提交前检查差异、敏感信息、原始资料和案例事实污染。评审问题修复后由主责提交，复核记录与交付版本共同归档。

### 5.4 变更控制

需求变更须由双方书面确认，并附范围、进度、技术、测试、数据、风险和交付影响分析。若变更影响冻结 Baseline 或正式里程碑，先登记 Issue 和变更记录，经评审确认后发布新版本；旧版本继续保留。

### 5.5 质保与服务安排

M5 后进入 12 个月质保服务期。A 维护服务台账与渠道记录，B 按三级 SLA 提供技术支持：一级故障 30 分钟响应、4 小时恢复或临时方案；二级故障 30 分钟响应、2 小时解决、最迟 1 个工作日；三级故障 8 小时响应、2 小时提出意见、5 个工作日解决。应急申告渠道为 7×24，远程支持渠道为 7×12；服务期满由 A 依据台账形成服务期满报告。该安排对应 WBS 6.8、6.9，不改变 M1—M5 正式里程碑。
