## 1. 项目定位

**一句话定位：**本系统是博物馆智能运营中心中连接日常应急准备、突发事件处置和事后改进的业务闭环与融合指挥子系统。【分析性结论；依据：需求书 §1.1、§1.2、§3.4】

系统以数字化预案为核心、应急指挥中心为枢纽、移动处置为延伸，覆盖预案、资源、演练、事件和值班的线上管理，并通过应急信息视图、综合安防视图和数据接口形成统一态势与协同处置能力。[来源：需求书 §1.2.1、§3.1、F-01 至 F-11]

它不替代视频监控、入侵报警、出入口控制、消防报警、广播、客流统计等既有系统，也不重复建设其前端硬件；其职责是通过接口接收数据、调阅资源和触发经授权的联动，将既有感知与安防能力纳入应急业务闭环。[来源：需求书 §1.3（3）、§3.2（1）、§3.3、FR-11.1 至 FR-11.3]

## 2. 建设背景与业务问题

### 2.1 原文明确指出的背景与目标

博物馆是人员密集公共场所，同时承担不可再生文物藏品保护责任；突发事件覆盖社会安全、自然灾害、火灾和运行事故等多类情形。免费开放后观众增长及节假日、暑期大客流进一步提高公共安全管理要求。[来源：需求书 §1.1]

需求书明确描述当前管理痛点：预案分散且启动依赖人工通知，指挥调度缺少统一平台，人员与物资底数不清，演练和值班管理缺少系统支撑，事件接报至事后调查缺乏全过程闭环。[来源：需求书 §1.1（1）至（5）]

建设目标是形成覆盖“事前预防准备—事发监测预警—事中处置救援—事后善后改进”的应急指挥处理中心，实现数字化预案、统一指挥、移动处置、全过程留痕与跨系统联动。[来源：需求书 §1.1、§1.2]

### 2.2 从需求结构得出的业务问题分析

- 【分析性结论】预案、人员、物资、值班和演练若分别管理，突发事件发生时仍需临时查找与人工协调；将这些日常数据与事件流程关联，才能让“平时维护”转化为“战时可调用”。[依据：需求书 §1.3（2）、§3.4、F-01、F-03、F-04、F-06]
- 【分析性结论】安防、消防、视频和物联网系统已经提供感知或控制能力，但数据若停留在各自系统中，无法自然形成应急事件、统一态势和处置任务；本项目的业务价值来自联动编排而非重复采集。[依据：需求书 §3.2（1）、§3.3、F-02、F-10、F-11]
- 【分析性结论】指挥中心与移动端必须形成双向闭环：中心下发任务并掌握态势，现场人员接收、处置和反馈；缺少任一方向都会留下“指令已发但执行不可见”或“现场有信息但中心不掌握”的断点。[依据：需求书 §3.4（1）（4）、FR-02.1、FR-05.3、FR-08.1、FR-08.2]
- 【分析性结论】评估、调查、知识沉淀和预案修订将单次事件或演练的记录转化为持续改进输入，避免流程只停留在“关闭事件”而没有组织学习。[依据：需求书 §3.4（1）（2）（4）、FR-04.3、FR-05.4]

## 3. 项目核心价值

### 3.1 应急响应价值

将事件接报、核实审批、预案启动、通知与任务下发、现场处置、进展反馈、关闭评估和事故调查置于同一生命周期，可减少人工交接造成的信息断点，使事件状态、责任人和处置证据持续可见。[来源：需求书 §3.4（1）（4）、FR-05.1 至 FR-05.4；分析性结论]

### 3.2 指挥协同价值

人员位置、视频、物资站点、事件状态和任务进展围绕事发地点集中呈现，使指挥人员能够基于同一态势组织调派，并通过移动反馈验证指令执行情况。【分析性结论；依据：需求书 §1.2.2（2）、FR-02.1 至 FR-02.4、FR-08.2】

### 3.3 平战结合价值

日常的预案维护、值班排班与打卡、资源盘点、演练执行和评估，为真实事件预先准备可调用的流程、人员、物资和经验；真实事件的评估与调查再反向推动知识和预案更新。[来源：需求书 §1.3（2）、§3.4；分析性结论]

### 3.4 系统融合价值

项目复用统一业务运行中台、平台消息通道、物联网平台以及既有安防和信息发布系统，通过标准接口把告警、视频、消息和联动动作接入应急流程。价值在于形成跨系统业务协同，同时避免把既有子系统与前端硬件重复计入建设范围。【分析性结论；依据：需求书 §1.3（3）、§3.2（1）、§3.3、F-11】

### 3.5 管理规范化与留痕价值

预案版本、审批、任务、事件续报、打卡、盘点、演练、评估和调查记录结构化保存，可支持过程追踪、复盘、责任核验和需求—测试—验收追踪，减少分散记录造成的缺失与口径不一。[来源：需求书 FR-01.4、FR-03.2、FR-04.2 至 FR-04.3、FR-05.2 至 FR-05.4、FR-06.1 至 FR-06.3、§10.2（1）；分析性结论]

### 3.6 安全与持续运行价值

系统要求部署于招标人内部环境，按角色控制敏感数据访问并记录审计；同时要求连续运行、消息失败重试、未完成任务恢复和后备电源条件下关键功能持续运行。这些要求共同保障应急系统在关键时刻可用、数据可控、操作可追溯。【分析性结论；依据：需求书 §4.2、§6.3、§7.5、§7.6】

## 4. 建设范围 In Scope

F-07 应急基础管理作为横向支撑范围，包含预案类型、事件类型、物资站点、评估报告模板和事件核实审批流程配置；这些能力分别服务于下述预案、事件、资源和评估流程，不另拆成平行项目。[来源：需求书 F-07，FR-07.1 至 FR-07.5]

### 4.1 应急预案管理

建设预案信息录入与编制、分层分类组织、处置流程与任务配置、通知人与调派人员设置、附件管理、检索修订和版本追踪能力，并支持预案启动时自动通知和任务下发。[来源：需求书 F-01，FR-01.1 至 FR-01.4]

### 4.2 应急指挥

建设面向当前应急事件的一张图指挥界面，展示事件动态、任务进展、周边应急人员、视频和物资站点信息，支持调派与处置跟踪。[来源：需求书 F-02，FR-02.1 至 FR-02.4]

### 4.3 应急资源

建设应急人员档案与职责/小组管理、值班计划、物资站点与物资台账、有效期提醒、盘点计划和差异核查能力。范围是信息化管理，不包含人员、物资或定位设备采购。[来源：需求书 F-03，§3.2（2）]

### 4.4 应急演练

建设月/季/年演练计划、周期任务自动下发、移动执行、过程记录、评估报告和持续改进记录能力，并区分演练数据与真实事件数据。[来源：需求书 F-04、FR-08.4、§7.4（3）]

### 4.5 应急事件

建设 Web/移动/外部告警来源的事件发起、检索、核实审批、生命周期跟踪、预案启动、任务下发与催办、关闭评估、事故调查和报告输出能力。[来源：需求书 F-05，FR-05.1 至 FR-05.4]

### 4.6 应急值班

建设打卡小组与代执行配置、地图点位与二维码、打卡任务、范围校验、就位统计和缺卡/超时预警能力，支撑关键岗位值班与带班制度落实。[来源：需求书 F-06，FR-06.1 至 FR-06.4]

### 4.7 移动端

建设移动事件上报、应急任务接收与反馈、知识库、演练执行、扫码打卡和物资盘点六类能力；确定采用 H5 嵌入现有智慧管理 APP，交付 H5 包，不另行建设原生 APP，宿主 APP 与发布由甲方负责。[来源：需求书 F-08，FR-08.1 至 FR-08.6；甲方模拟书面澄清第 7 项]

### 4.8 应急信息视图与综合安防视图

建设应急事件、任务、演练、值班与监控等运行指标的统计展示，以及既有安防终端在线状态和告警的集中展示、定位与业务跳转能力。[来源：需求书 F-09、F-10，FR-09.1、FR-10.1]

### 4.9 数据与系统接口

建设与物联网平台、统一业务运行中台、视频监控、信息发布、安防消防、短信/统一消息通道的接口及联动记录，并向经授权的其他子系统提供标准化开放接口和接口文档。[来源：需求书 §3.3、F-11、§8.1 至 §8.3]

### 4.10 配套文档 实施 培训与服务

范围包括需求、设计、接口、测试、用户、部署运维、合规与追踪等交付文档，部署与基础数据初始化配合，分角色培训、联动演练支持、试运行、验收配合及质保期服务。[来源：需求书 §9.1 至 §9.4、§10.1 至 §10.4]

## 8. 业务闭环

```text
事件发现或上报
  → 核实与审批
  → 启动相应预案
  → 通知与处置任务下发
  → 指挥调度与资源协同
  → 移动现场处置
  → 进展和结果反馈
  → 事件关闭
  → 应急评估与事故调查
  → 知识沉淀与预案修订
```

该闭环由预案提供流程与任务模板，人员和物资提供可调派资源，值班提供持续接报与就位保障，演练验证流程并产生改进输入，视频和地图提供态势，统一消息提供指令触达，外部接口提供告警与联动能力。[来源：需求书 §3.4（1）（4）、F-01 至 F-08、F-11；分析性结论]

## 9. 主要项目约束

- 必须复用并对接既有视频、安防、消防、信息发布、物联网平台和统一业务运行中台；中台通用能力只做业务适配，不重复建设。[来源：§1.3（3）、§3.2、§3.3；甲方模拟书面澄清第 5 项]
- 软件在招标人内部私有环境运行；依赖组件须能在与互联网逻辑隔离的环境安装部署。服务器、网络、域名证书、备份介质和后备电源由甲方提供，乙方提交最低配置与部署方案。[来源：§3.2（3）、§4.2（1）、§4.3（5）、§6.3（1）；甲方模拟书面澄清第 8 项]
- 建设形态包含 Web 端、H5 移动端、指挥视图、数据接口及配套文档/培训服务；H5 嵌入甲方现有智慧管理 APP，不另行交付原生 APP。[来源：§3.1、§4.1、§4.2（4）；甲方模拟书面澄清第 7 项]
- 视频历史回放为强制范围，但录像存储及不低于 30 天保存由既有视频系统承担；本项目负责接口调阅、回放和验证。[来源：§3.3（1）、FR-02.3、FR-11.3、§8.1（1）；甲方模拟书面澄清第 1 项]
- 人员定位展示须使用甲方提供的亚米级源数据，刷新不超过 2 秒且不得降低源精度；定位基础设施不属于本项目采购范围。[来源：FR-02.2、PE-05、§3.2（2）；甲方模拟书面澄清第 2 项]
- 消息调用须具备并发、重试、回执与留痕，并在正常验收通道验证不低于 20 路并行和不低于 99% 到达率；通道、短信账号/签名/配额由甲方既有平台提供。[来源：§4.3（4）、FR-08.2、PE-04；甲方模拟书面澄清第 4 项]
- 应按不低于等保二级中与应用软件直接相关的条款建设；甲方负责最终定级/备案和基础环境，乙方负责应用侧安全、SCA、漏洞扫描、渗透测试和高危清零；正式第三方等保测评不默认属于乙方范围。[来源：§7.6、§10.2（4）；甲方模拟书面澄清第 11 项]
- 预案体系、演练、系统设计和验收文档受需求书列明的法律法规与标准规范约束；★条款不允许负偏离。[来源：§1.3（4）、§2]
- 系统需满足需求书规定的连续运行、后备电源条件下关键功能持续运行、数据安全与审计要求；本工作稿不新增安全等级或服务承诺。[来源：§1.3（5）、§4.2（2）、§6.3、§7.5、§7.6]
- 业务类型、流程和模板应可配置，并通过标准接口支持后续扩展和第三方集成。[来源：§1.3（6）、§4.3（1）（4）、§8.3]
- 需求变更须经双方书面确认；文档、代码与测试证据要保持版本一致和双向追踪。[来源：§9.2（3）（4）、§10.4]
