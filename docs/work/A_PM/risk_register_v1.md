## 1 风险清单

### 1.1 编制依据与使用规则

本登记册管理第一关编标阶段已识别的实施、验收和过程风险，不将风险判断表述为已发生事实或验收结论。项目事实、关键数字、甲乙责任和正式里程碑以 `BASELINE-G1-V0.1` 及用户需求书为准；技术触发信号与建议措施吸收 B 的 `G1-04_technical_risk_input.md`。G1-06 项目计划 v1 仍处 `REVIEW`，凡引用其 WBS、阶段、里程碑或三人资源安排的关联项均标注“待 G1-06 Review 后复核”。

### 1.2 评估口径

- 概率（P）：1 很低、2 较低、3 中等、4 较高、5 很高。
- 影响（I）：1 轻微、2 较小、3 一般、4 严重、5 重大，综合考虑范围、验收、进度、数据安全和运行影响。
- 风险等级：评分为 `P × I`；1—4 为低、5—9 为中、10—16 为高、17—25 为极高。评分用于安排跟踪优先级，不替代用户需求书的验收判定。
- 状态：本版均为“监控中”。历史澄清 Issue 已关闭，其关联仅用于追溯责任边界，不代表当前阻塞。

## 2 跟踪机制

1. A 每周根据周报、接口前置条件、测试记录、数据对账、部署和运行证据更新风险状态、触发条件、责任人和措施有效性；重大风险按需求书要求在识别后 24 小时内书面报告甲方。
2. RR-01、RR-03、RR-04、RR-08、RR-10、RR-13 为极高风险，按周形成专项跟踪记录；触发后先保护事件、任务、消息和审计等核心链路，再评估对正式里程碑的影响。
3. 与 M2 相关的接口、视频和消息风险必须在设计评审前形成真实连通性验证记录；不能把模拟服务或自动检查结果写成真实连通结论。
4. 与数据、部署、安全、性能和验收相关的风险，分别以数据对账、干净环境部署、SCA/扫描/渗透复测、性能实测和需求追踪证据作为关闭依据。
5. 历史 Issue 的关闭仅表示需求解释已裁决。发生新的接口、环境、数据或验证问题时，A 新建 Issue 或变更记录，不覆盖已关闭历史。
6. G1-06 项目计划 v1 完成 C 的 Review 前，RR-01—RR-08、RR-10—RR-11、RR-13—RR-14、RR-16 的 WBS、阶段和资源关联须由 A 与 C 复核；本登记册不修改 G1-06。
7. 风险关闭必须同时满足：触发条件解除或已被控制、预防/应急措施有执行证据、残余影响已评估、关联 Issue/测试/验收记录可回溯，并由相应责任人和复核人确认。无证据的风险不得标记为关闭。
