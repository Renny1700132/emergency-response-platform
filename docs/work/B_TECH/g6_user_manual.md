## 1 引言

### 1.1 阅读对象

本手册面向应急指挥员、事件核实人员、现场安保员、任务执行人员、物资保障人员、值班人员和系统管理员。Web 端用于态势查看、事件核实、预案启动、任务统筹和事件关闭；H5 嵌入既有智慧管理 APP，用于移动事件上报、任务接收反馈、扫码打卡、物资盘点和知识查询。

### 1.2 系统能力与边界

- Web/H5 支持事件上报、核实、预案启动、任务接收/反馈/完成，以及授权后的事件关闭；
- 关闭操作保存评估结论、调查/处置报告引用与关闭时间，并校验全部响应任务已完成；
- 统一中台提供身份、权限和文件能力，应用保留 traceId、审计与幂等记录；
- 视频、消息、定位、GIS、安防和信息发布六类甲方真实系统仍为 `REAL_WORLD_DEFERRED`；
- 预案、资源、演练、值班、知识和集成工作台在正式模式当前以查询为主，演示按钮不代表生产写能力。

## 2 快速开始

### 2.1 登录与入口

1. 在既有智慧管理门户登录，由门户传递 Bearer 令牌。
2. Web 根路径进入 `/web/overview`；移动端从宿主 APP 打开 `/h5/events`。
3. 未登录显示“需要登录”；缺权限显示“无访问权限”。演示模式额外显示“演示数据”。

## 3 角色与权限

角色由统一中台提供，一个人员可拥有多个角色，最终以权限集合和数据范围为准。

表 3-1 典型角色与操作边界

| 典型角色 | 主要权限点 | 允许操作 | 禁止或受限操作 |
| --- | --- | --- | --- |
| 应急指挥员/关闭评估人员 | `incident:verify`、`incident:start-response`、`incident:close`、`task:create` | 核实、启动、统筹任务，在前置条件满足后关闭事件 | 无授权不得关闭；不得绕过未完成任务或伪造报告引用 |
| 现场安保员 | `incident:create`、`task:acknowledge`、`task:feedback`、`task:complete` | 上报事件、接收和反馈任务 | 未获授权不得核实、启动或关闭事件 |
| 物资保障员 | `resource:read`、`inventory:write`、`task:feedback` | 查询资源、盘点和反馈 | 页面无正式入口时不得把演示按钮当生产操作 |
| 值班人员 | `duty:read`、`attendance:write`、`incident:create` | 查看值班、扫码打卡、上报发现 | 不得查看超出数据范围的记录 |
| 系统管理员 | 中台分配的配置和集成权限 | 配置角色映射、接口参数和字典 | 不得替代业务审批或删除审计事实 |

## 4 事件全流程

### 4.1 上报、核实与启动处置

进入“事件管理”上报事件。具备 `incident:verify` 的人员确认或驳回并填写说明。仅对已确认事件选择已发布预案版本并启动处置。遇到 409 应刷新最新资源版本，不能连续重复提交。

![事件处置](../../../evidence/g6/G6-01/screenshots/02-web-incidents-presentation.png)

### 4.2 关闭评估、报告材料与结果核对

1. 确认事件为 `RESPONDING`，且全部响应任务为 `COMPLETED`；否则服务返回 409/422，事件保持原状态。
2. 在统一文件能力中归档调查/处置报告或材料，取得受控文件 ID 或报告编号。页面只保存报告引用。
3. 使用具有 `incident:close` 权限的账号进入 `/web/incidents`，展开“关闭评估 / 调查报告”。
4. 填写关闭评估结论和报告引用，两项均为必填；点击“提交关闭评估”。无权限时按钮显示“无关闭权限”。
5. 页面刷新后核对状态为 `CLOSED`，并核对关闭结论、报告引用和关闭时间；保存事件编号、时间与 traceId。
6. 409 时刷新任务；422 时补齐输入；403 时申请授权，不得使用他人账号。

知识工作台当前正式模式只提供已发布知识查询，不提供知识编辑或沉淀入口。知识整理属于后续受控工作，不是被静默绕过的关闭前置条件。

### 4.3 关闭验证证据

V0.2 在正式 API Client 组件路径和本地实际 HTTP 路径验证了关闭操作：页面校验权限和两项输入；服务校验事件状态及任务完成情况；成功返回 `CLOSED`、`closureConclusion`、`closureReportRef` 和 `closedAt`。自动化证据为 `frontend/tests/page-interactions.test.ts` 与 `frontend/tests/real-stack-e2e.test.ts`；后者使用内存存储及模拟外部提供方，不构成 PostgreSQL 事件关闭验证或甲方现场验收。PostgreSQL 部署、目标回退和备份恢复证据单独见命令执行台账。

## 5 任务接收、反馈与完成

在 H5“我的任务”接收任务，提交文字、0—100 的进度和附件引用；网络失败时保留输入并重试。2026-10-12 技术确认：当前发布快照包含 `8dbfbab` 的 H5 最新反馈进度映射修复，服务端最新反馈可正确显示，显式 0 不会被旧值覆盖。关闭事件前必须确保全部响应任务完成。

## 7 状态、提示与错误处理

表 7-1 页面状态与用户处置

| HTTP | 含义 | 用户处置 |
| --- | --- | --- |
| 401 | 未建立统一中台身份 | 返回宿主门户重新登录 |
| 403 | 缺权限或数据范围 | 申请授权并提供页面、时间、traceId |
| 404 | 资源不存在或不可见 | 刷新列表并确认编号 |
| 409 | 状态、版本或幂等冲突 | 重新加载最新记录 |
| 422 | 业务规则不满足 | 补必填项或满足前置条件 |
| 429 | 访问过于频繁 | 停止重复提交，稍后重试 |
| 503 | 中台或外部端口不可用 | 使用降级路径并记录 traceId |

不得把 Bearer 令牌、数据库口令或敏感附件内容粘贴到问题单。

## 11 术语

表 11-1 术语与定义

| 术语 | 含义 |
| --- | --- |
| traceId | 贯穿请求、日志和审计的追踪标识 |
| Outbox | 与业务事实同事务保存的待发送事件记录 |
