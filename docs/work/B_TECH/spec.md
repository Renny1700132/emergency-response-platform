### 1.1 通用验收约束

| 主题 | 适用规则 | 验收处理 |
| --- | --- | --- |
| 身份、组织、权限 | 使用甲方统一中台既有能力；本系统仅做应急业务适配。 | 以授权/未授权访问、审计记录和中台联调证据验证。 |
| 移动端 | 交付嵌入既有智慧管理 APP 的 H5，不另建原生 APP。 | 宿主、签名、发布及目标终端矩阵为甲方/联调前置，待 M2 确认。 |
| 视频与定位 | 既有系统提供录像保存、定位源和验收环境；本系统负责接口、关联、展示和验证。 | 回放、首帧、刷新及源精度在目标接口和环境中实测，不预填结果。 |
| 消息与门禁 | 消息走甲方既有统一通道；门禁经授权确认并服从安全联锁。 | 通道回执、重试、留痕、失败告警和人工降级须形成联调证据。 |
| 审计与异常 | 关键操作、状态变化、接口调用和失败处理应可追溯。 | 每个场景以业务结果、状态/审计记录或外部回执作为观察证据。 |

## 2 MVP 需求与验收标准

### G2-FR-001｜FR-01.1｜★｜分层应急预案

- 需求：系统应支持综合、专项、现场三级预案，并按分区、分时、分险细化。
- 前置：预案管理员已获授权；预案分类、适用区域、时段和风险标签可选。
- 验收标准：
  - AC-G2-FR-001-01：**Given** 管理员进入预案编制，**When** 新建综合预案并关联专项和现场预案，**Then** 系统保存三级关系并可按层级查看。
  - AC-G2-FR-001-02：**Given** 已有预案，**When** 设置分区、分时或分险适用条件，**Then** 系统保存条件并在检索结果中显示。
  - AC-G2-FR-001-03：**Given** 无编辑权限的用户，**When** 尝试新增或修改预案，**Then** 系统拒绝操作并留存授权失败审计。

### G2-FR-002｜FR-01.2｜★｜预案流程与资源编排

- 需求：系统应配置预案流程、任务、会议群组、通知对象及调派人员。
- 前置：管理员已取得组织、人员与权限目录；流程编排数据有效。
- 验收标准：
  - AC-G2-FR-002-01：**Given** 管理员编辑预案，**When** 增加流程节点、任务和责任人，**Then** 系统保存顺序、责任和依赖关系。
  - AC-G2-FR-002-02：**Given** 预案需要协同，**When** 配置会议群组和通知对象，**Then** 系统在预案版本中保留配置并可供启动时读取。
  - AC-G2-FR-002-03：**Given** 人员目录不可用或对象失效，**When** 保存编排，**Then** 系统提示不可用项，不将失效对象作为可执行调派对象。

### G2-FR-003｜FR-01.3｜★｜启动预案自动下发任务

- 需求：系统应支持自定义任务，并在预案启动时自动向移动终端下发。
- 前置：已发布预案含有效任务；接收人具备 H5 访问和统一消息通道条件。
- 验收标准：
  - AC-G2-FR-003-01：**Given** 管理员在预案中新增自定义任务，**When** 保存并发布预案，**Then** 任务名称、责任人、时限和执行状态可被读取。
  - AC-G2-FR-003-02：**Given** 已核实事件并选择有效预案，**When** 授权人员启动预案，**Then** 系统自动创建对应处置任务并向移动端发送通知。
  - AC-G2-FR-003-03：**Given** 验收通道和目标设备可用，**When** 启动预案，**Then** 从启动到通知/任务下发满足 KN-003 的 ≤3 秒指标；未满足时记录测量结果与异常，不宣称通过。

### G2-FR-004｜FR-02.1｜★｜事件态势与任务动态

- 需求：系统应实时展示事件动态、续报、时间线、任务状态和处理人。
- 前置：事件、续报和任务均以关联标识写入；查看人具备事件查看权限。
- 验收标准：
  - AC-G2-FR-004-01：**Given** 已创建事件，**When** 有人提交续报，**Then** 事件时间线按发生/接收时间展示续报及来源。
  - AC-G2-FR-004-02：**Given** 事件关联任务，**When** 任务被接收、反馈或完成，**Then** 态势视图显示当前状态和处理人。
  - AC-G2-FR-004-03：**Given** 未获事件权限的用户，**When** 访问事件详情，**Then** 系统拒绝展示受限内容并记录访问审计。

### G2-FR-005｜FR-02.2｜★｜人员定位与就位状态

- 需求：系统应在地图展示周边人员动态、职责和就位状态；刷新不超过 2 秒且不得降低甲方提供的亚米级源精度。
- 前置：甲方提供定位源、人员关联、坐标/楼层映射和验收环境；数据新鲜度可判断。
- 验收标准：
  - AC-G2-FR-005-01：**Given** 定位源返回有效人员位置，**When** 指挥人员打开事件地图，**Then** 系统叠加人员位置、职责和就位状态。
  - AC-G2-FR-005-02：**Given** 连续定位数据可用，**When** 执行目标环境性能测试，**Then** 刷新周期满足 KN-008 ≤2 秒/次，且处理后精度不低于 KN-009 的源精度；结果以测试记录判定。
  - AC-G2-FR-005-03：**Given** 位置过期或源不可用，**When** 用户查看地图，**Then** 系统标识新鲜度/不可用状态，并禁止将其作为自动邻近调派结论。

### G2-FR-006｜FR-02.3｜★｜视频调阅与历史回放

- 需求：系统应通过既有视频接口实现一键实时调阅和历史回放；不新建录像存储，既有系统负责不少于 30 天保存。
- 前置：甲方提供 GB/T 28181 等接口资料、账号和历史录像；用户具备授权。
- 验收标准：
  - AC-G2-FR-006-01：**Given** 用户选择有权限的视频点位，**When** 发起实时调阅，**Then** 系统通过既有接口请求并展示实时画面或明确失败原因。
  - AC-G2-FR-006-02：**Given** 既有系统存在指定时段录像，**When** 用户检索并回放，**Then** 系统通过接口完成调阅，不创建或承担录像存储。
  - AC-G2-FR-006-03：**Given** 目标视频环境可用，**When** 执行首帧与保存条件验证，**Then** 首帧按 KN-010 ≤3 秒测量，保存条件按 KN-060 ≥30 天由既有系统证据确认。

### G2-FR-007｜FR-02.4｜非★｜物资站点一张图

- 需求：系统应在地图展示物资站点，并钻取清单、数量和配置。
- 前置：物资站点、台账和地图服务已完成基础导入及关联。
- 验收标准：
  - AC-G2-FR-007-01：**Given** 已配置物资站点坐标，**When** 打开态势地图，**Then** 系统展示站点图层。
  - AC-G2-FR-007-02：**Given** 用户选择一个站点，**When** 打开站点详情，**Then** 系统展示该站点的物资清单、数量和配置。
  - AC-G2-FR-007-03：**Given** 站点无有效台账关联，**When** 用户钻取详情，**Then** 系统提示数据缺失并保留异常记录，不展示虚构数量。

### G2-FR-008｜FR-03.3｜★｜物资台账与临期提醒

- 需求：系统应维护物资台账、数量、有效期并提供临期提醒。
- 前置：物资管理员已获授权；物资类别和站点可关联。
- 验收标准：
  - AC-G2-FR-008-01：**Given** 管理员录入物资，**When** 保存名称、数量、有效期和站点，**Then** 系统生成可查询台账记录。
  - AC-G2-FR-008-02：**Given** 台账物资临近有效期，**When** 执行提醒规则，**Then** 系统生成临期提醒并记录触发时间。
  - AC-G2-FR-008-03：**Given** 验收数据规模达到约定基线，**When** 导入台账和站点，**Then** 系统可承载 KN-023 ≥30 站点、KN-024 ≥1000 项的验证数据，结果以导入与查询证据判定。

### G2-FR-009｜FR-03.4｜★｜盘点计划与差异标识

- 需求：系统应制定盘点计划，支持移动盘点、自动比对并标识差异。
- 前置：台账存在有效数量；移动端接入可用；盘点对象与计划范围已确定。
- 验收标准：
  - AC-G2-FR-009-01：**Given** 管理员选择站点和物资，**When** 创建盘点计划，**Then** 系统保存计划范围和台账快照。
  - AC-G2-FR-009-02：**Given** 现场人员打开计划，**When** 提交移动盘点数量，**Then** 系统将结果与计划快照自动比对并标识差异。
  - AC-G2-FR-009-03：**Given** 出现盘点差异，**When** 管理员复核处理，**Then** 系统保留原快照、盘点值、复核人和处理结果。

### G2-FR-010｜FR-04.1｜★｜演练计划与频次

- 需求：系统应制定月、季、年演练计划，并落实监管频次。
- 前置：演练管理员具备计划维护权限；适用场所和计划周期可选。
- 验收标准：
  - AC-G2-FR-010-01：**Given** 管理员新建演练计划，**When** 选择月、季或年周期及场所，**Then** 系统保存计划、责任人和目标时间。
  - AC-G2-FR-010-02：**Given** 人员密集场所被纳入监管，**When** 检查任一滚动六个月，**Then** 系统可验证每半年至少一次演练安排（KN-013）。
  - AC-G2-FR-010-03：**Given** 计划冲突或缺少责任人，**When** 发布计划，**Then** 系统阻止发布或给出可追溯的校验提示。

### G2-FR-011｜FR-04.2｜★｜演练任务自动下发

- 需求：系统应在演练周期到达时自动下发演练任务并留痕。
- 前置：已发布演练计划含触发周期、任务和接收对象；消息通道可联调。
- 验收标准：
  - AC-G2-FR-011-01：**Given** 到达计划触发时间，**When** 系统执行计划调度，**Then** 自动创建对应演练任务。
  - AC-G2-FR-011-02：**Given** 演练任务已创建，**When** 通知下发，**Then** 系统记录接收对象、下发时间、回执或失败状态。
  - AC-G2-FR-011-03：**Given** 消息通道不可用，**When** 下发失败，**Then** 系统进入重试/告警或人工处置流程并留痕。

### G2-FR-012｜FR-04.3｜★｜演练评估与改进

- 需求：系统应记录演练执行、使用模板完成评估、生成报告并跟踪持续改进。
- 前置：演练任务和评估模板已存在；评估人具备授权。
- 验收标准：
  - AC-G2-FR-012-01：**Given** 演练正在执行，**When** 人员提交执行记录，**Then** 系统关联计划、任务、人员和时间。
  - AC-G2-FR-012-02：**Given** 执行记录完成，**When** 评估人按模板评分，**Then** 系统保存评估条目、结论和附件引用。
  - AC-G2-FR-012-03：**Given** 评估发现整改项，**When** 创建改进措施，**Then** 系统可追踪整改状态并在报告中关联展示。

### G2-FR-013｜FR-05.1｜★｜Web/H5 事件发起与检索

- 需求：系统应支持 Web/H5 发起事件并按多条件检索。
- 前置：用户已通过统一身份认证；事件类型和基础数据可用。
- 验收标准：
  - AC-G2-FR-013-01：**Given** 授权用户在 Web 或 H5 端，**When** 提交事件基本信息，**Then** 系统创建事件并生成可追踪编号。
  - AC-G2-FR-013-02：**Given** 存在多个事件，**When** 用户按时间、状态、类型或关键字组合检索，**Then** 系统返回符合条件的事件列表。
  - AC-G2-FR-013-03：**Given** 必填字段缺失或用户无权限，**When** 提交事件，**Then** 系统拒绝提交并提示原因，不生成不完整事件。

### G2-FR-014｜FR-05.2｜★｜事件核实、启动与生命周期

- 需求：系统应完成事件核实审批、预案启动、生命周期跟踪和留痕。
- 前置：事件已创建；核实人和授权启动人已由权限体系识别。
- 验收标准：
  - AC-G2-FR-014-01：**Given** 新事件等待核实，**When** 核实人提交通过或驳回意见，**Then** 系统记录意见、处理人、时间和状态变更。
  - AC-G2-FR-014-02：**Given** 事件已核实且预案可用，**When** 授权人员启动预案，**Then** 系统进入处置生命周期并关联预案与任务。
  - AC-G2-FR-014-03：**Given** 目标验收环境可用，**When** 测量告警接入和任务下达，**Then** 分别按 KN-011 ≤2 秒、KN-012 ≤3 分钟形成测试记录。

### G2-FR-015｜FR-05.3｜★｜处置任务反馈与催办

- 需求：系统应自动下发处置任务，支持反馈、催办和临时任务。
- 前置：事件已启动预案或授权人员已创建临时任务；接收对象有效。
- 验收标准：
  - AC-G2-FR-015-01：**Given** 预案启动，**When** 系统生成处置任务，**Then** 任务自动关联事件、责任人、时限和状态。
  - AC-G2-FR-015-02：**Given** 任务已接收，**When** 执行人提交反馈，**Then** 系统记录反馈内容、附件引用、时间和处理状态。
  - AC-G2-FR-015-03：**Given** 任务逾期或指挥人员需追加任务，**When** 触发催办或创建临时任务，**Then** 系统记录触发原因和后续处置。

### G2-FR-016｜FR-05.4｜★｜事件关闭、调查与知识沉淀

- 需求：系统应支持关闭评估、事故调查、报告和知识沉淀。
- 前置：事件处置任务已进入可关闭状态；关闭人具备授权。
- 验收标准：
  - AC-G2-FR-016-01：**Given** 事件满足关闭条件，**When** 关闭人提交评估，**Then** 系统记录评估结论和关闭状态。
  - AC-G2-FR-016-02：**Given** 需要事故调查，**When** 填写调查记录并生成报告，**Then** 系统关联事件证据、调查结论和报告版本。
  - AC-G2-FR-016-03：**Given** 事件已关闭，**When** 用户检索历史处置，**Then** 系统可在授权范围内查询其时间线、报告和知识条目。

### G2-FR-017｜FR-06.1｜★｜值班打卡规则

- 需求：系统应配置值班打卡小组、时段、点位，并记录代执行。
- 前置：值班管理人员已获授权；人员、小组和点位数据有效。
- 验收标准：
  - AC-G2-FR-017-01：**Given** 管理员设置值班规则，**When** 选择小组、时段和点位，**Then** 系统保存可执行的打卡配置。
  - AC-G2-FR-017-02：**Given** 需要代执行，**When** 管理员按授权指定代执行人，**Then** 系统记录授权关系、操作者和时间。
  - AC-G2-FR-017-03：**Given** 配置存在无效人员或点位，**When** 发布规则，**Then** 系统提示并阻止无效配置生效。

### G2-FR-018｜FR-06.2｜★｜打卡点位、二维码和半径

- 需求：系统应维护打卡点位、支持地图拾取、二维码和有效半径。
- 前置：甲方地图服务可用；点位管理员已获授权。
- 验收标准：
  - AC-G2-FR-018-01：**Given** 管理员在地图选择位置，**When** 保存打卡点，**Then** 系统保存坐标、楼层和点位属性。
  - AC-G2-FR-018-02：**Given** 已保存点位，**When** 生成或更新二维码和有效半径，**Then** 系统将其与点位关联并保留版本记录。
  - AC-G2-FR-018-03：**Given** 地图服务或坐标不合法，**When** 保存点位，**Then** 系统提示失败原因且不产生无效点位。

### G2-FR-019｜FR-06.3｜★｜打卡统计与导出

- 需求：系统应按点位、小组、人员统计打卡，并导出明细。
- 前置：存在打卡记录；查看人具有相应范围权限。
- 验收标准：
  - AC-G2-FR-019-01：**Given** 已产生打卡记录，**When** 用户选择统计周期，**Then** 系统按点位、小组、人员三个维度汇总（KN-014）。
  - AC-G2-FR-019-02：**Given** 用户筛选统计条件，**When** 导出明细，**Then** 导出内容与当前权限和筛选范围一致。
  - AC-G2-FR-019-03：**Given** 无权限用户尝试导出，**When** 发起导出，**Then** 系统拒绝并记录审计。

### G2-FR-020｜FR-06.4｜★｜缺卡告警与消息推送

- 需求：系统应对缺卡/超时告警并经甲方统一消息通道推送。
- 前置：值班规则和接收对象有效；甲方提供消息通道、账号、签名和配额。
- 验收标准：
  - AC-G2-FR-020-01：**Given** 已到打卡截止时间且无有效记录，**When** 规则引擎检查，**Then** 系统创建缺卡或超时告警。
  - AC-G2-FR-020-02：**Given** 告警需要通知，**When** 调用统一消息通道，**Then** 系统记录请求、重试、回执或失败结果。
  - AC-G2-FR-020-03：**Given** 正常验收通道可用，**When** 执行并发测试，**Then** ≥20 路、≥99% 到达率按 KN-006、KN-007 实测并保留结果；未通过时进入异常处置。

### G2-FR-021｜FR-08.1｜★｜H5 事件发起与个人事件

- 需求：H5 应支持移动发起事件、拍照并查看个人事件。
- 前置：H5 已嵌入甲方既有智慧管理 APP；用户完成认证并授予相机权限。
- 验收标准：
  - AC-G2-FR-021-01：**Given** 授权用户打开 H5，**When** 发起事件并拍照上传，**Then** 系统保存事件、图片引用和提交人。
  - AC-G2-FR-021-02：**Given** 用户已有本人发起或参与的事件，**When** 打开个人事件，**Then** 系统仅展示其授权范围内的事件。
  - AC-G2-FR-021-03：**Given** 相机或网络不可用，**When** 用户提交事件，**Then** H5 明确提示可恢复状态并防止把未上传附件标记为已上传。

### G2-FR-022｜FR-08.2｜★｜H5 任务接收、反馈和完成

- 需求：H5 应支持移动接收、确认、反馈、上传和完成任务。
- 前置：任务已下发；用户为任务接收人；统一消息与 H5 宿主可联调。
- 验收标准：
  - AC-G2-FR-022-01：**Given** 用户收到任务通知，**When** 在 H5 确认任务，**Then** 系统更新任务接收状态并留痕。
  - AC-G2-FR-022-02：**Given** 任务执行中，**When** 用户提交反馈和附件，**Then** 系统关联任务、上传结果和时间。
  - AC-G2-FR-022-03：**Given** 任务条件满足，**When** 用户提交完成，**Then** 系统更新任务状态；消息并发与到达率按 KN-006、KN-007 在正常验收通道验证。

### G2-FR-023｜FR-08.4｜★｜H5 演练执行

- 需求：H5 应支持查看、执行演练并提交结果。
- 前置：演练任务已下发给当前用户；用户具有执行权限。
- 验收标准：
  - AC-G2-FR-023-01：**Given** 用户有待执行演练，**When** 打开 H5 演练列表，**Then** 系统展示本人授权任务及状态。
  - AC-G2-FR-023-02：**Given** 用户进入演练任务，**When** 提交执行结果，**Then** 系统记录结果、时间和关联任务。
  - AC-G2-FR-023-03：**Given** 任务已关闭或用户无权限，**When** 尝试提交，**Then** 系统拒绝并保留可追溯提示。

### G2-FR-024｜FR-08.5｜★｜H5 扫码打卡

- 需求：H5 应支持扫码打卡，并校验身份、时段和范围。
- 前置：有效打卡规则、二维码、点位和用户身份已配置；宿主具备扫码能力。
- 验收标准：
  - AC-G2-FR-024-01：**Given** 用户扫描有效点位二维码，**When** 身份、时段和范围均符合规则，**Then** 系统写入有效打卡记录。
  - AC-G2-FR-024-02：**Given** 用户不在有效半径、时段或小组内，**When** 扫码，**Then** 系统拒绝打卡并说明失败维度。
  - AC-G2-FR-024-03：**Given** 目标环境可用，**When** 执行扫码写入测试，**Then** 按 KN-036 ≤1 秒记录性能结果。

### G2-FR-025｜FR-08.6｜★｜H5 物资盘点

- 需求：H5 应支持移动盘点物资并更新现有数量。
- 前置：已发布盘点计划；计划快照和当前用户权限有效。
- 验收标准：
  - AC-G2-FR-025-01：**Given** 用户打开本人盘点计划，**When** 录入或扫描物资盘点数量，**Then** 系统关联计划、物资和现场记录。
  - AC-G2-FR-025-02：**Given** 用户提交盘点，**When** 系统校验计划快照，**Then** 自动标识与快照的数量差异。
  - AC-G2-FR-025-03：**Given** 盘点结果经授权复核，**When** 确认更新，**Then** 系统更新现有数量并保留盘点和复核证据。

### G2-FR-026｜FR-10.1｜★｜综合安防视图

- 需求：系统应展示安防终端在线、告警统计、定位和跳转。
- 前置：甲方既有安防接口和地图服务可用；用户具备查看权限。
- 验收标准：
  - AC-G2-FR-026-01：**Given** 接入终端在线状态和告警数据，**When** 打开综合安防视图，**Then** 系统展示在线状态、告警统计和空间定位。
  - AC-G2-FR-026-02：**Given** 用户选择终端或告警，**When** 发起业务跳转，**Then** 系统跳转至关联业务上下文或明确记录失败原因。
  - AC-G2-FR-026-03：**Given** 目标环境具备验收数据，**When** 测量视图刷新，**Then** 按 KN-016 ≤30 秒形成测试证据。

### G2-FR-027｜FR-11.1｜★｜物联网告警与客流接入

- 需求：系统应接入物联网告警/客流，实现告警转事件、断连重试和补传。
- 前置：甲方提供接口资料、账号、环境和联调窗口；事件类型映射已配置。
- 验收标准：
  - AC-G2-FR-027-01：**Given** 物联网接口推送有效告警，**When** 系统接收并匹配规则，**Then** 创建或关联应急事件并保留原始关联信息。
  - AC-G2-FR-027-02：**Given** 接口暂时断连，**When** 连接恢复，**Then** 系统按重试/补传策略处理并记录成功、失败或待人工处置状态。
  - AC-G2-FR-027-03：**Given** 不可识别的告警或客流数据，**When** 接收处理，**Then** 系统不自动生成错误事件，并输出可审计的异常记录。

### G2-FR-028｜FR-11.2｜★｜统一中台业务适配

- 需求：系统应适配甲方统一中台的身份、组织、权限、消息、工作流、文件、门户和数据汇聚能力，不重复建设通用平台能力。
- 前置：甲方提供中台接口与联调条件；应急业务映射已配置。
- 验收标准：
  - AC-G2-FR-028-01：**Given** 中台返回用户、组织或权限信息，**When** 用户访问应急业务，**Then** 系统按中台授权执行业务访问控制。
  - AC-G2-FR-028-02：**Given** 应急业务需要消息、流程或文件能力，**When** 发起相应调用，**Then** 系统通过中台适配层调用并记录关联结果。
  - AC-G2-FR-028-03：**Given** 中台接口不可用，**When** 业务访问受影响，**Then** 系统展示可观察错误并记录降级/人工处置，不以本地重复建设替代中台通用能力。

### G2-FR-029｜FR-11.3｜★｜视频回放与受权门禁联动

- 需求：系统应实现视频调阅/历史回放，并应支持经授权确认、安全联锁的疏散门禁联动；失败告警并人工降级。
- 前置：视频和门禁接口资料、账号、环境与窗口已由甲方提供；操作人具备授权；门禁安全联锁有效。
- 验收标准：
  - AC-G2-FR-029-01：**Given** 用户具有视频权限且既有录像可用，**When** 发起调阅或历史回放，**Then** 系统通过既有接口完成请求、记录结果并遵循既有系统保存责任。
  - AC-G2-FR-029-02：**Given** 疏散场景满足业务条件，**When** 授权人员确认开启门禁，**Then** 系统向既有门禁发送指令并等待安全联锁结果，不绕过联锁。
  - AC-G2-FR-029-03：**Given** 门禁拒绝、超时或联锁失败，**When** 接收失败回执，**Then** 系统产生告警、保留回执并转入人工降级处置。

  - AC-G2-FR-031-02：**Given** 人员已加入有效小组，**When** 触发调派通知，**Then** 系统记录接收对象、时间和回执或失败状态。
  - AC-G2-FR-031-03：**Given** 人员已失效或无调派权限，**When** 被选作调派对象，**Then** 系统提示并阻止无效下发。

  - AC-G2-FR-032-02：**Given** 已发布计划，**When** 调整人员或时段，**Then** 系统保存调整前后内容、操作者和时间。
  - AC-G2-FR-032-03：**Given** 调整与现有打卡规则冲突，**When** 提交变更，**Then** 系统提示冲突并阻止无效规则生效。

### G2-FR-033｜FR-07.1｜非★｜预案类型维护

  - AC-G2-FR-033-02：**Given** 类型已被预案引用，**When** 管理员停用该类型，**Then** 历史预案保留原类型，新建预案不能再选择该类型。
  - AC-G2-FR-033-03：**Given** 无权限用户，**When** 尝试维护类型，**Then** 系统拒绝操作并记录审计。

### G2-FR-034｜FR-07.2｜★｜事件类型维护

  - AC-G2-FR-034-02：**Given** 已配置预置类别，**When** 管理员维护类别，**Then** 系统允许按权限调整，不将预置类别误写为新增强制范围。
  - AC-G2-FR-034-03：**Given** 类型已被事件引用，**When** 停用类型，**Then** 历史事件保留可查，新建事件不能选择该类型。

### G2-FR-035｜FR-07.3｜★｜物资站点空间配置

- 验收标准：

  - AC-G2-FR-039-03：**Given** 目标环境可用，**When** 测量默认刷新，**Then** 按 KN-017 ≤60 秒形成性能验证记录。
