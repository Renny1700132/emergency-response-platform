## 2 G1 上游继承索引（不计入 G2 新澄清）

### G2-CLR-001｜视频录像、回放与保存责任

- **AI 反向问题**：历史录像回放是强制能力时，本项目是否要新建录像平台并承诺保存时长？
- **影响**：若把既有录像存储纳入本项目，将错误扩大采购、部署、容量和验收责任；若弱化回放，则会遗漏强制功能。
- **既有人工裁决**：历史录像回放为强制要求；录像产生、存储和不少于 30 天保存由既有视频系统负责；本项目负责接口接入、实时调阅、历史回放和验证，不新建录像存储。
- **裁决来源**：DEC-001；F-106；KN-010、KN-060。
- **双镜像落点**：SRS G2-FR-006、G2-FR-029；spec AC-G2-FR-006-01—03、AC-G2-FR-029-01。
- **验证与证据**：M2 前完成视频连通；在既有录像和授权账号条件下实测回放与首帧，保存条件以既有系统证据确认。
- **结论**：已裁决；不改变需求范围，现场能力仍待验证。

### G2-CLR-002｜定位源精度与刷新责任

- **AI 反向问题**：≤2 秒刷新和亚米级精度是否意味着乙方需要建设定位基站并保证源精度？
- **影响**：错误归责会造成范围外硬件承诺；未声明源精度边界会导致验收对象不清。
- **既有人工裁决**：甲方提供定位基础设施、源数据和验收所需亚米级能力；乙方负责接口、人员关联、坐标/楼层映射、展示和不超过 2 秒刷新，且不得降低源精度。
- **裁决来源**：DEC-002；F-105；KN-008、KN-009。
- **双镜像落点**：SRS G2-FR-005；spec AC-G2-FR-005-01—03。
- **验证与证据**：在甲方验收环境比较源/展示时间戳与精度；对过期或不可用位置标识新鲜度并禁止自动邻近调派结论。
- **结论**：已裁决；定位基础设施不纳入本项目，链路性能待现场验证。

### G2-CLR-003｜疏散门禁联动的授权与降级

- **AI 反向问题**：系统接到疏散事件后，能否自动绕过既有门禁联锁直接开门？
- **影响**：自动越权或绕过安全联锁会引入安全风险；不定义失败路径则无法验证降级行为。
- **既有人工裁决**：门禁联动提升为“应支持”；授权人员确认后下发开启指令，服从既有门禁安全联锁，失败时告警并人工降级。
- **裁决来源**：DEC-003；F-138。
- **双镜像落点**：SRS G2-FR-029；spec AC-G2-FR-029-02—03。
- **验证与证据**：用授权、拒绝、超时和联锁失败场景检查指令、回执、告警和人工处置记录；不以未联调结果宣称联动成功。
- **结论**：已裁决；仅受权联动，不绕过既有安全机制。

### G2-CLR-004｜统一消息通道与指标口径

- **影响**：自建会重复甲方既有能力；使用非验收通道会使指标证据无效。
- **既有人工裁决**：甲方提供统一消息通道、短信账号/签名/配额；乙方负责调用、并发、重试、回执与留痕；在正常验收通道内验证≥20 路、≥99%。
- **裁决来源**：DEC-004；F-122、F-129；KN-006、KN-007。
- **双镜像落点**：SRS G2-FR-020、G2-FR-022；spec AC-G2-FR-020-02—03、AC-G2-FR-022-03。
- **验证与证据**：M2 前连通；以通道请求、回执、重试和并发统计记录验证，失败进入告警或人工处置。
- **结论**：已裁决；消息通道本体不纳入建设，指标尚待实测。

- **既有人工裁决**：统一中台提供身份、组织、权限、消息、工作流、文件存储、门户和数据汇聚；乙方只做应急业务适配，不重复建设通用平台能力。

### G2-RCLR-001｜重复外部告警的事件去重边界

- **规格来源与歧义**：G2-FR-014、G2-FR-027；相同告警重复到达时，是创建新事件、自动合并，还是更新既有告警未明确。
- **影响**：重复建事件会造成任务、统计和审计重复；仅凭类型/地点自动合并又可能吞并两个真实事件。
- **备选口径**：A. 每次均新建事件；B. 按外部唯一 ID 幂等，无可靠 ID 时人工关联；C. 按类型、地点和时间窗自动合并。
- **人工裁决**：采用 B。相同可靠外部唯一告警 ID 不重复创建事件，作为同一告警的重复接收或更新；后续有效内容进入续报/处理记录。无可靠唯一 ID 时不得仅凭同类型、同地点自动合并，由人工判断关联。
- **裁决证据**：同 §3.1 原文证据第 1 项。
- **双镜像落点**：SRS G2-FR-014/027 的告警接入与核实流程；spec 对应 AC 增加重复 ID、内容更新、无 ID 人工关联场景；RTM 挂接本编号。
- **验证方式**：同一唯一 ID 重放不新增事件且保留接收记录；同 ID 新内容形成更新/续报；无 ID 相似告警保持独立并提供人工关联入口。

- **验证方式**：配置超时后状态转为核实超时或仍待核实，有提醒/升级记录，事件不自动生效且预案不自动启动。

- **影响**：覆盖原责任人会破坏问责链；自动重置截止时间会掩盖逾期，自动保留又可能不符合新安排。
- **备选口径**：A. 覆盖原责任人并重置期限；B. 保留完整历史、默认不重置期限，变更须显式审计；C. 禁止重指派。
- **人工裁决**：采用 B。完整保留原责任人、重指派时间、操作者、原因和历史；当前责任转给新责任人。截止时间默认不重置，如修改必须人工显式操作并审计。
- **裁决证据**：同 §3.1 原文证据第 3 项。
- **双镜像落点**：SRS G2-FR-015/022 的任务状态与审计规则；spec 增加重指派及显式改期 AC；RTM 挂接本编号。
- **验证方式**：重指派后当前责任人正确，原责任和操作原因可查；未改期时截止时间不变，显式改期产生独立审计记录。
- **状态**：DECIDED_COURSE_PROJECT / PENDING_B_A_REVIEW。

### G2-RCLR-004｜事件时间线的多时间语义

- **规格来源与歧义**：G2-FR-004、G2-FR-013/014；业务发生时间、源时间、接收时间和记录时间不一致时排序与修订规则未明确。
- **影响**：按接收顺序展示会扭曲现场顺序；迟到数据覆盖历史会破坏审计和复盘。
- **备选口径**：A. 仅保存系统接收时间；B. 保存多时间并优先业务发生时间展示，迟到数据追加标识；C. 迟到数据回写覆盖原记录。
- **人工裁决**：采用 B。保存业务发生/源时间、系统接收时间和记录时间；时间线优先按业务发生时间展示，同时显示接收时间；迟到数据标记为迟报/晚到，不覆盖历史。
- **裁决证据**：同 §3.1 原文证据第 4 项。
- **双镜像落点**：SRS G2-FR-004/013/014 的数据与时间线规则；spec 增加乱序、迟到和历史不可覆盖 AC；RTM 挂接本编号。
- **验证方式**：构造乱序到达记录，展示按业务时间排序且接收时间可见；迟到项有标识，既有历史版本和审计仍可追溯。
- **状态**：DECIDED_COURSE_PROJECT / PENDING_B_A_REVIEW。

### G2-RCLR-005｜二维码有效期与重复扫码

- **规格来源与歧义**：G2-FR-017—020、G2-FR-024；二维码绑定范围、过期行为和重复扫码是否重复计为有效记录未明确。
- **影响**：长期有效或可重放二维码会削弱打卡可信度；重复计数会污染缺卡/超时统计。
- **备选口径**：A. 固定永久二维码且每次计数；B. 绑定任务/点位/时段并对同人同任务同点位幂等；C. 新增固定有效秒数。
- **人工裁决**：采用 B。二维码与打卡任务、点位和有效时段绑定；过期无效；同一人员同一任务同一点位重复扫码幂等，不重复形成有效打卡。具体有效时长由业务配置。
- **裁决证据**：同 §3.1 原文证据第 5 项。
- **双镜像落点**：SRS G2-FR-017—020/024；spec 增加绑定校验、过期拒绝、幂等重放 AC；RTM 挂接本编号。既有扫码≤1秒要求保持不变。
- **验证方式**：有效时段内首次扫码成功；过期码拒绝并说明原因；重复扫码不增加有效记录但保留必要审计。
- **状态**：DECIDED_COURSE_PROJECT / PENDING_B_A_REVIEW。

### G2-RCLR-006｜盘点快照与期间出入库

- **规格来源与歧义**：G2-FR-009、G2-FR-025；盘点期间台账变化时，差异应以实时值还是计划基准比较未明确。
- **影响**：直接使用实时台账会导致同一盘点结果随期间业务变化而漂移；冻结台账又会阻断正常出入库。
- **备选口径**：A. 盘点期间冻结所有出入库；B. 始终与实时台账比较；C. 以计划开始/发布快照为基准并单独记录期间变动，复核后调整。
- **人工裁决**：采用 C。以计划开始/发布时形成的库存快照为比对基准；盘点期间正常出入库单独记录；盘点结果与快照比对后进入复核，复核结合期间变动形成最终调整。
- **裁决证据**：同 §3.1 原文证据第 6 项。
- **双镜像落点**：SRS G2-FR-009/025 的盘点流程与数据规则；spec 增加快照、期间变动和复核 AC；RTM 挂接本编号。
- **验证方式**：盘点中产生出入库后，差异仍可回到原快照；复核界面同时呈现实盘、快照和期间变动，最终调整有依据。
- **状态**：DECIDED_COURSE_PROJECT / PENDING_B_A_REVIEW。

### G2-RCLR-007｜补演、逾期历史与完成统计

- **规格来源与歧义**：G2-FR-010—012、G2-FR-023；取消、未完成和后续补演如何计入频次、完成率及整改关闭未明确。
- **影响**：用补演覆盖原逾期会美化监管历史；完全不关联又无法证明整改闭环。
- **备选口径**：A. 补演覆盖原记录并视为按期完成；B. 补演独立且不关联；C. 关联原计划、保留逾期/未完成历史，按实际完成统计。
- **人工裁决**：采用 C。取消或未完成演练不计为完成；补演关联原计划并保留原计划时间、原因和实际完成时间。补演可关闭整改，但不得消除原逾期/未完成历史；统计以实际完成记录为准。
- **裁决证据**：同 §3.1 原文证据第 7 项。
- **双镜像落点**：SRS G2-FR-010—012/023；spec 增加取消、未完成、补演关联和统计 AC；RTM 挂接本编号。
- **验证方式**：原计划逾期后补演完成，整改可关闭但原逾期仍可查询；完成率和频次按实际完成记录计算。
- **状态**：DECIDED_COURSE_PROJECT / PENDING_B_A_REVIEW。

### G2-RCLR-008｜迟到与重复消息回执

- **规格来源与歧义**：G2-FR-020、G2-FR-022；已超时/降级后到达的回执是否更新最终状态，以及重复回执如何计数未明确。
- **影响**：忽略迟到回执会造成最终送达状态失真；覆盖失败历史或重复计数会破坏到达率、重试和人工处置证据。
- **备选口径**：A. 超时后忽略所有回执；B. 回执覆盖全部历史；C. 迟到回执更新最终送达但保留过程历史，重复回执幂等。
- **人工裁决**：采用 C。迟到回执仍关联原消息和发送尝试并更新最终送达状态，但不得删除超时、重试、降级或人工处置历史；重复回执幂等处理。
- **裁决证据**：同 §3.1 原文证据第 8 项。
- **双镜像落点**：SRS G2-FR-020/022；spec 增加迟到、乱序、重复回执与历史保留 AC；RTM 挂接本编号。≥20路与≥99% 仍须真实验收通道验证。
- **验证方式**：超时降级后注入迟到回执，最终状态更新且失败/人工历史仍在；重复回执不重复计入送达或产生重复业务动作。
- **状态**：DECIDED_COURSE_PROJECT / PENDING_B_A_REVIEW。

### G2-RCLR-009｜位置数据过期与调派禁用

- **规格来源与歧义**：G2-FR-005；定位数据多久算过期以及过期后能否继续形成“最近人员”或自动调派结论未明确。
- **影响**：使用陈旧位置自动决策可能误导应急调派；新增固定阈值又会形成无来源数字。
- **备选口径**：A. 永不过期；B. 新增统一固定秒数；C. 阈值可配置，过期仅显示最后有效位置并禁止自动调派结论。
- **人工裁决**：采用 C。不新增固定秒数，采用可配置阈值；超过阈值后显示最后有效位置及数据时间，并禁止基于过期位置自动形成最近人员或自动调派结论。正常刷新仍遵守既有≤2秒要求。
- **裁决证据**：同 §3.1 原文证据第 9 项。
- **双镜像落点**：SRS G2-FR-005；spec 增加新鲜度阈值、过期显示和调派禁用 AC；RTM 挂接本编号。KN-008、KN-009 数值与责任不变。
- **验证方式**：超过配置阈值后显示最后有效时间和过期状态，自动最近人员/调派不可用；恢复新数据后按合法状态恢复。
- **状态**：DECIDED_COURSE_PROJECT / PENDING_B_A_REVIEW。

### G2-RCLR-010｜附件逻辑删除、归档引用与物理清理

- **规格来源与歧义**：G2-FR-013、G2-FR-015、G2-FR-016、G2-FR-021/022；业务附件删除后审计、归档引用和物理清理边界未明确。
- **影响**：直接物理删除会破坏事件、任务、报告和审计证据；完全禁止清理又会绕过后续保留策略与容量治理。
- **备选口径**：A. 普通用户可直接物理删除；B. 永久禁止任何清理；C. 业务逻辑删除并保留审计，归档/关闭引用受保护，物理清理由后续保留策略控制。
- **人工裁决**：采用 C。业务删除采用逻辑删除并保留附件标识、关联对象、删除人、时间和原因等审计信息；已归档/已关闭业务引用附件不得由普通用户直接物理删除；物理清理由后续保留策略控制。
- **裁决证据**：同 §3.1 原文证据第 10 项。
- **双镜像落点**：SRS G2-FR-013/015/016/021/022 的附件与审计规则；spec 增加权限、逻辑删除、归档保护和可追溯 AC；RTM 挂接本编号。
- **验证方式**：逻辑删除后普通列表不可见但审计与业务引用可追溯；归档/关闭引用附件的普通物理删除被拒绝；本轮不新增无来源保存年限。
- **状态**：DECIDED_COURSE_PROJECT / PENDING_B_A_REVIEW。
