4 容器部署

4.1 部署步骤
在仓库根目录执行。以下命令已由 scripts/g6/run-g6-01-deployment-check.sh 在隔离项目
                                       中逐条运行并保存原始日志。
   export POSTGRES_PASSWORD='<从密钥设施注入>'
   export MIDDLE_PLATFORM_BASE_URL='https://<甲方中台地址>'
   docker compose build backend
   docker compose up -d --wait
   docker compose exec -T backend node backend/scripts/migrate.mjs up
   curl -fsS http://127.0.0.1:3000/healthz
   curl -fsS http://127.0.0.1:3000/readyz

/healthz 验证进程存活；/readyz 同时验证数据库可用。只有两者均为 200 才可进入业务
 冒烟。中台不可用时，受保护 API 会默认拒绝身份，但不能因此伪造中台健康结论。

8 备份与恢复

8.1 备份
  建议执行每日增量、每周全量，最终制度由甲方确认。执行前确认备份介质、保留
                            期、加密和访问权限。
  docker compose exec -T database sh -lc \
    'pg_dump -U emergency -d emergency -Fc -f /tmp/emergency.dump && sha256sum
  /tmp/emergency.dump'
  docker compose cp database:/tmp/emergency.dump ./backup/emergency.dump


8.2 恢复演练
不得直接覆盖生产库。先恢复到隔离数据库，核对表数、关键哨兵、迁移版本和业务
                       抽样，再由有权人员批准切换。
  docker compose exec -T database createdb -U emergency emergency_restore
  docker compose exec -T database pg_restore -U emergency -d emergency_restore \
      --exit-on-error /tmp/emergency.dump
  docker compose exec -T database psql -U emergency -d emergency_restore \
      -Atqc "SELECT count(*) FROM pg_tables WHERE schemaname='public';"

本轮在隔离 Compose 项目实跑后，恢复前后均为 37 张表，审计哨兵均为 1；这不证明
                    甲方生产备份介质、主备切换或 RPO/RTO 已验收。

9 升级与回退

9.1 升级前
锁定 commit/镜像摘要，运行质量门禁，保存当前配置差异，完成备份和恢复抽检，核
 对 migration up/down，确认维护窗口、通知人和回退责任。任何真实接口或账号未到
                               位时标记阻断，不临时改成模拟地址。

9.2 升级
   docker compose pull
   docker compose build backend
   docker compose up -d --wait
   docker compose exec -T backend node backend/scripts/migrate.mjs up
   curl -fsS http://127.0.0.1:3000/healthz
   curl -fsS http://127.0.0.1:3000/readyz


9.3 回退
触发条件包括核心接口持续失败、迁移错误、数据完整性异常、严重安全问题或批准
AC 失败。停止扩散，保留日志和 traceId，切回上一已知良好镜像/commit；数据库只
使用已验证的 down 脚本或恢复点。不可逆变更必须走前向修复和 CCB，不得直接删
                                           除数据。
   docker compose exec -T backend node backend/scripts/migrate.mjs down
   git checkout <上一批准发布标签>
   docker compose build backend
   docker compose up -d --wait

 migrate down 只能在变更评估确认不会丢失有效业务数据后执行；本手册不授权对生
                                      产库直接运行。
