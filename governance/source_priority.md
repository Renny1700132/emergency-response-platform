# 信息源优先级与冲突预检

## 优先级

1. P0：当前用户直接下达的 Prompt / 当前任务指令
2. P1：真实项目《用户需求书》
3. P2：《通关实验任务书》
4. P3：《AI 辅助软件项目全生命周期开发·综合实习指导书（学生用书）》
5. P4：教学案例
6. P5：AI 推理、经验与常识

不同资料各司其职：用户需求书管真实项目事实；任务书管当前关卡提交物、评分和过关条件；指导书管方法论与工程纪律；案例只管结构与表达参考。

## Prompt 优先权的边界

P0 可决定工作方式、文件组织、AI 使用策略、日志策略和当前任务范围。P0 不得被 AI 自行扩大为“可以改变真实项目需求”。

功能需求、★实质性条款、性能指标、项目边界、验收条件、甲方职责、质保/SLA 与法规标准以真实《用户需求书》为准。若当前用户明确要求修改上述事实，执行前必须特别警告、列出影响并等待确认。

## Preflight Conflict Check

任何有实际产出的任务在修改前必须：

1. 确认 Task ID、输入、主责与复核人。
2. 仅在允许范围内列出资料；明确课件只登记不读取。
3. 检查 Prompt 与用户需求书、任务书、指导书之间的规则冲突。
4. 对每项冲突给出编号、文档规则、Prompt 规则、采用规则和评分/审计影响。
5. 判断是否涉及真实项目事实与是否必须暂停。
6. 普通方法论冲突在提示后按 P0 继续，并写入 `control/overrides.md`。

只有以下情况必须暂停：可能导致原始资料丢失；无法判断哪个真实项目需求有效；可能造成不可逆 Git/文件系统操作；或用户要求更改真实项目关键事实但尚未确认。

## 课件与案例

明确标注为课程课件的 PPT/PDF 不读取、不解析、不作为规则来源。教学案例不得向 `control/facts.md`、`control/key_numbers.md` 或正式响应引入案例事实。
