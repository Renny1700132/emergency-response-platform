## 2. 剩余阻断 Finding

### ISSUE-G4-03-002｜MAJOR｜运行时幂等 header 名与冻结契约不一致

冻结 `docs/work/B_TECH/openapi_v1.yaml:2925-2928` 和 `interface_design.md:34` 明确 header 名为 `X-Idempotency-Key`。`frontend/src/shared/http/api-client.ts:121` 却执行 `headers.set('Idempotency-Key', ...)`；`frontend/tests/api-client.test.ts:37` 也只断言错误名称，因而本地质量门禁会把不符合契约的请求误判为通过。

影响：正式后端/网关按冻结契约读取 `X-Idempotency-Key` 时可能无法取得客户端幂等键，导致写请求被拒绝，或失去重试去重保护。类型层虽然已补齐，但运行时并未真正实现同一契约，`ISSUE-G4-03-002` 仍不能关闭。

最小修复：

1. 将运行时发送 header 改为 `X-Idempotency-Key`。
2. 将测试断言同步改为 `X-Idempotency-Key`，并明确断言旧的 `Idempotency-Key` 不存在。
3. 修正 selfcheck/整改说明中“运行时契约已完成”的口径，复跑完整 `npm run quality`。
