## 2. 剩余阻断 Finding

### ISSUE-G4-03-002｜MAJOR｜必填 operation 参数仍可省略

`frontend/src/shared/http/api-client.ts` 已从 `paths[P][method]` 推导 `PathParameters`，但 `OptionalTransportOptions` 仍固定声明 `path?: PathParameters<P,M>`；同时没有推导 operation 的必填 header，`idempotencyKey?: string` 对所有请求均为可选。

冻结生成类型明确显示：

- `GET /api/v1/incidents/{incidentId}` 的 `parameters.path.incidentId` 为必填；当前 `client.get('/api/v1/incidents/{incidentId}')` 仍可通过类型检查，运行时 URL 会保留未替换占位符。
- 写操作如 `POST /api/v1/incidents/{incidentId}/verify` 的 `X-Idempotency-Key` 为必填；当前调用可不传 `idempotencyKey`。

现有 `frontend/tests/api-client.types.ts` 只覆盖错误方法、错误 body、GET body 和错误响应赋值，没有覆盖“缺少必填 path”和“缺少必填幂等键”两个负例。因此 A 整改记录所称“从 operation 推导 path”和 selfcheck 的 contract PASS 仍不完整，上轮 Issue 关闭条件未满足。

最小修复：

1. 根据 `PathParameters<P,M>` 是否为 `never`，条件化要求 `path`；存在必填 path 参数时不得省略。
2. 从 operation header 参数或写操作规则推导必填幂等键；至少冻结契约中要求 `X-Idempotency-Key` 的操作必须要求 `idempotencyKey`。
3. 增加两个 `@ts-expect-error` 负例：缺失必填 path、缺失必填幂等键；增加对应运行时 path 替换测试。
4. 修正 selfcheck 与整改记录，复跑完整 `npm run quality`。
